== Scope and Standard

Evaluates `verification-ecosystem/vext` (the Vext protocol *specification* repo —
the cryptographic one, not `vcs-ircd` and not `vexometer/vext`) against
*Component Readiness Grades v2.0 (STRICT)*, 2026-03-30 revision.

- Standard: `standards/component-readiness-grades/COMPONENT-READINESS-GRADES.md`
- Criteria boilerplate: `rsr-template-repo/docs/governance/CRG-CRITERIA.adoc`
- Self-declared grade source:
  * `.machine_readable/6a2/STATE.a2ml` -> `[status] / grade = "C"`,
    `version = "0.1.0"`, `phase = "spec"`, `readiness = "C # 7/10 (Spec Complete)"`
- Audit date: 2026-04-18
- Auditor: Jonathan D.A. Jewell

This audit grades the repo *as-is today*, not aspirationally.

=== Schema drift note (three-way)

Vext STATE.a2ml uses a *third* schema variant for its CRG declaration. Estate-wide,
three different shapes exist in the wild:

[cols="1,3,3"]
|===
| Variant | Shape | Example repo

| Flat | `crg-grade = "C"` at top level | burble (pre-audit), most Bucket-B repos
| Nested `[crg]` | `[crg]` section with `grade`, `completion-percentage` | sanctify-php
| Nested `[status]` | `[status]` section with `grade`, `phase`, `readiness` | *vext (this repo)*
|===

This drift is flagged for standardisation but not resolved in this audit. Vext's
`[status]` form is the *least* common of the three and complicates automated
`rg -n 'crg-grade|\[crg\]'` starter sweeps — such sweeps would return an empty
match here and risk misreading the repo as "ungraded".

== v2.0 Strictness Recap

[cols="1,3,4"]
|===
| Grade | Release Stage | Hard Requirement (v2.0)

| X | None             | Untested.
| F | Reject           | Harmful, wasteful, or superseded.
| E | Pre-alpha        | >=1 test, failures documented.
| D | Alpha            | Test matrix + scope documented + *RSR compliance mandatory*.
| C | Alpha-stable     | Dogfooded, CI green, *deep per-file + per-directory annotation*.
| B | Beta             | 6+ *diverse* external targets, issues fed back.
| A | Stable           | Real-world external feedback confirms value; no harm.
|===

Publication requires B+. Long alpha is discipline, not shame.

== Verdict

*Current CRG grade: **X (None)**.*

Under v2.0 STRICT, the E floor is "at least one test with failures
documented". Vext has zero tests, zero source files, and zero workflow runs.
The declared "C # 7/10 (Spec Complete)" readiness is not defensible: the spec
itself is not in this repo — only the promise of one. The README's
"Structure" section documents `src/proofs/`, `src/ref/`, and `spec/`
directories that *do not exist on disk*.

The self-declared `C` is a four-grade overclaim.

Strongest *positive* signals (there are some):

1. Name disambiguation is genuinely well done — the three-way collision with
   `vcs-ircd` and `vexometer/vext` is explained in both `README.adoc` and
   `0-AI-MANIFEST.a2ml`, which prevents a real future source of confusion.
2. Downstream consumer exists and is substantial: Burble's
   `vext.ex` + `vext_groove.ex` + `vext_test.exs` total 531 LOC of Elixir
   implementing the protocol concept. If this content were lifted upstream,
   the repo would have genuine D/E footing.
3. The repo is honestly *marked* as `phase = "spec"` — the drift is in the
   grade, not the phase. An honest phase + honest grade would be
   `phase = "spec"` + `grade = "X"` (or `grade = "E"` once a single
   property-based test of the hash-chain claim is written).

What blocks *immediate* promotion to E:

1. Write at least one test that executes *something* in this repo. A
   property test of the BLAKE3 hash-chain linking rule, even in 10 lines of
   Rust with one `cargo test` invocation, satisfies the E floor.
2. Create `tests/` or `src/ref/tests/` to house it.
3. Add `.github/workflows/ci.yml` that runs the test.

What blocks promotion to D after that:

1. RSR structural baseline: add `Justfile`, `guix.scm` (+`flake.nix`
   fallback), the remaining five canonical A2ML files (META, ECOSYSTEM,
   AGENTIC, NEUROSYM, PLAYBOOK), `docs/EXPLAINME.adoc`,
   `docs/READINESS.md`, `.well-known/` baseline, and the contractile
   trident.
2. Populate the directories the README already promises: `src/proofs/` (at
   least one Idris2 file typechecking green), `src/ref/` (a skeleton Rust
   crate), and `spec/` (even a one-page protocol sketch counts as "scope
   documented").
3. Reconcile README against reality — either build the directories or
   rewrite the README to match the 5-file state honestly.

What blocks promotion to C after that:

1. Pull Burble's `vext.ex` protocol logic *upstream* into `src/ref/` (or
   reference it canonically) so the spec repo owns its own behaviour.
2. Deep per-directory annotation (READMEs in every subtree).
3. Green CI history and a `[dogfooding-status]` section with dated entries.

== Notes on Non-Negotiables Respected by this Audit

- The repo *is* GitHub-only on origin, which respects the single-forge
  push policy.
- SPDX headers are present on the two files that carry content
  (`README.adoc`, `0-AI-MANIFEST.a2ml`).
- The LICENSE pointer style (one-line reference rather than full PMPL
  text) is noted but not penalised — the policy permits this pending the
  canonical PMPL license file at `hyperpolymath/palimpsest-license`.
- No `believe_me` / `assert_total` / `Admitted` / `sorry` risk because
  there is no Idris2 code at all.

- Flat `crg-grade = "C"` (most common)

across the estate without a three-way grep disjunction. If nesting is
preferred, `[crg]` is more descriptive than `[status]` (which conflates
grade, phase, and readiness into one section).
